# Старт двух параллельных проектов в Codex

## Цель
Создать два самостоятельных MVP, не смешивая их код и задачи:

1. `revenue-diagnostic` — калькулятор скрытой выручки как лид-магнит.
2. `content-factory` — внутренний ИИ-контент-завод агентства с SaaS-ready архитектурой.

## Порядок действий

1. Создать **два закрытых репозитория** в GitHub: `revenue-diagnostic` и `content-factory`.
2. В первый положить `ТЗ_Калькулятор_скрытой_выручки.md` и `PROMPT_01_Калькулятор.md`.
3. Во второй положить `ТЗ_ИИ_Контент_завод.md` и `PROMPT_02_Контент_завод.md`.
4. Открыть Codex Cloud на вебе, войти с учётной записью ChatGPT, подключить GitHub, создать/выбрать среду для каждого репозитория. Если нужного интерфейса нет, проверить доступность Codex Cloud в настройках аккаунта.
5. Запустить **отдельные задачи** по содержимому файлов `PROMPT_01...` и `PROMPT_02...`.
6. В первом ответе потребовать план, карту файлов и список блокирующих решений; затем разрешить первый небольшой, проверяемый этап с тестами.
7. Проверить результаты двух задач самостоятельно, не публиковать сайты без проверки, не загружать реальные клиентские данные и фотографии детей в тестовый проект.

## Приоритет ближайшей итерации

- Калькулятор: расчётное ядро, словарь показателей, проверки финансовых формул и предотвращения двойного счёта.
- Контент-завод: приём тестовых материалов, карточка клиента, брендбук, готовые сторис из утверждённых шаблонов, базовый редактор и сохранение черновиков.

## Ограничения

- Никаких платных API и публикаций в интернет без отдельного разрешения.
- Никаких действительных персональных/финансовых данных клиентов в демо.
- В первой итерации — без полноценной интеграции MAX, автоматического доступа к существующим чатам, SaaS-биллинга и полноценного ИИ-редактора с голосовыми командами.
- Время, которое ИИ тратит на генерацию, не учитывается как трудочасы сотрудников.

## Как оценивать прогресс

Каждая задача Codex должна заканчиваться:
- перечнем изменений;
- инструкцией локального запуска/просмотра;
- командами тестов и их результатами;
- известными ограничениями и следующим небольшим шагом.

Не объединяйте репозитории до появления работающих и проверенных MVP.
