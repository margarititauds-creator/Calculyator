# Правила проекта
Не публиковать и не подключать платные API без явного запроса. Не выдумывать нормативы. Сохранять независимость core.js от UI. Любые изменения формул проверять контрольными суммами и тестами пересечений. Команда проверки: npm test. Демо-данные только вымышленные.

## Сохранение документов

Постоянное требование владельца от 11.11.2026: документы этого проекта сохранять сразу в папке проекта на ПК и в GitHub-репозитории `margarititauds-creator/Calculyator` (прежний адрес `margarititauds-creator/revenue-diagnostic` перенаправляется на него). Под «сервером» владелец понимает Git, а не Yandex Cloud. Ссылка на файл в облачной среде или архив для ручного скачивания не заменяют сохранение на ПК.

Перед записью определить фактические папки проекта и доступность каждого назначения. Существующие документы пользователя не перезаписывать неизвестной или более старой версией. Документы хранить в разделе `docs` соответствующей копии проекта, если в ней не принят другой порядок.

После сохранения проверить существование и содержимое файлов в обоих местах; при передаче готовых файлов сверять SHA-256. Сообщать фактические пути и статус каждой копии. Не утверждать, что синхронизация настроена или файл сохранён на ПК/сервере, пока запись там не выполнена и не проверена.

Сохранять подготовленные документы в Git с осмысленным коммитом и отправлять в репозиторий. Не включать посторонние изменения, ключи и конфиденциальные клиентские данные. Репозиторий на момент проверки публичный; учитывать аудиторию перед добавлением новых материалов.

Если сессия не имеет доступа к ПК или GitHub, сохранить доступную копию и явно обозначить, какое подключение требуется. Облачная рабочая папка Codex, копия на ПК и GitHub — отдельные места хранения; успешная запись в одном не подтверждает запись в остальных. Сохранение документов не означает запуск сайта или создание ресурсов Yandex Cloud.
