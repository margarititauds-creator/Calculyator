Подтверждённый результат
Закрытая проверка облачного отправителя прошла. Сервер Sites сам получил сохранённую вымышленную анкету из российской YDB, расшифровал её, проверил согласие и отправил отчёт в настроенного Telegram-бота. Независимое чтение базы подтвердило delivered и Telegram messageId 8.
После этого публичная отправка включена. Независимое чтение YDB подтвердило совпадение квитанции, вымышленного контакта и расчёта; запись зашифрована, состояние delivered, Telegram messageId 9. Проверка выполнялась через технический адрес сайта.

Домен

Облачное расписание
Создана связанная с Sites задача Automation_d9346a0135748191bd49732aeb09b6b3 «Доставлять анкеты калькулятора в Telegram». Она включена, интервал — один час, часовой пояс Asia/Yekaterinburg. Первый плановый запуск указан на 24.11.2026 21:00 (+05:00).
Создание расписания ещё не подтверждает успешное выполнение. Нужен результат реального запуска с доступом к инструменту deliver_calculator_queue.
Начальный текст задачи содержит проверку фиксированной вымышленной анкеты перед очередью. После подтверждения доступа его следует заменить обычной последовательностью calculator_delivery_health → deliver_calculator_queue без обязательного повторного теста: иначе удаление тестовой записи по сроку хранения остановит задачу.
Инструмент Codex automation_update поддерживает изменение локальных cron/heartbeat, поэтому изменение этой облачной задачи через него не выполнено. Вход в веб-управление расписанием через разрешённый Google-аккаунт остановился на сетевой ошибке accounts.google.ru. Новый Google-доступ, чтение почты или Drive не использовались.

Дополнение после 16:08 UTC
Первый фактический запуск облачной задачи не получил инструменты calculator_delivery_health / verify_calculator_delivery / deliver_calculator_queue. Задача сообщила об отсутствии доступа и приостановилась; get_site независимо подтвердил is_enabled=false. Поэтому автоматические повторы пока не работают.
Для управления подключением выполнен разрешённый владельцем вход через Google. В Edge открыта страница OpenAI «Подтвердите вашу личность», требуется личное подтверждение владельца. Коды или пароли в чат не запрашиваются. Обычный служебный токен Sites не заменяет OAuth-доступ к MCP: безопасная проверка обнаружения команд вернула HTTP 401, без попытки обхода авторизации.

Вторая внешняя проверка интерфейса нашла контактные поля на третьем шаге после выбора «Хочу обсудить расчёт». Форма объявляла отправку доступной. Однако при отправке вымышленной анкеты через внешний браузер получила «Отправка разрешена только с сайта калькулятора.» и статус failed. Доставка этой анкеты не подтверждена.
Отдельная проверка API с Origin собственного домена показала: GET /api/config — 200, ready=true и правильный Access-Control-Allow-Origin; POST /api/status для уже доставленной вымышленной записи — 200, sent и тот же правильный CORS-заголовок. Для технического адреса CORS также разрешён. Причина различия между внешним браузером и прямой проверкой пока не установлена; ослабление проверки Origin не выполнялось.
Серверный маршрут отправки и его подтверждение в YDB работают, но полноценный запуск для всех посетителей и автоматические повторы ещё не доказаны. Следующие необходимые проверки: завершить личное подтверждение входа, проверить/подключить собственный MCP-плагин и возобновить расписание без зависимости от срока хранения тестовой записи; установить фактический Origin браузерной отправки и повторить отправку через интерфейс.
